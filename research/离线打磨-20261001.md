# 持续离线打磨

阶段约束：用户于 2026-10-01 要求在暂不启动游戏验证的前提下持续打磨，后续得到允许后统一验证。本轮没有启动游戏、模拟器，没有安装 APK，没有重启正式服务；所有接口测试使用临时数据库和随机回环端口。

## 本轮实现

### 普通花园

接通 `010901` 放入花园、`020102` 花园信息、`010302` 幼年期成长。

- 同时最多 3 只，来自原 `990701.codeM.maxChildMonster`。
- 只接受当前账号持有、非蛋、具有匹配 `990110` 成长路线的幼年期数码兽；保护编队、战斗和培养中的状态。
- 同一只重复放入不重置倒计时、不重复占位，重新认证/服务重新实例化后仍保留倒计时。
- 幼年期 I → 幼年期 II → 成长期沿捕捉时已固定的路线成长，保留拥有编号、技能/锁定等非成长字段，并按新物种主数据重算等级和基础属性。
- 第一次成长后继续在花园等待第二阶段；第二次完成后释放名额。
- 自然到期不扣石；提前成长检查客户端持有数与服务端余额，并原子扣费。失败批次整体回滚，同会话原请求重试不重复扣费。
- 幼年期和正在培养的数码兽禁止喂食、编队、出战。该批当时尚未实现研究与数码蛋孵化；第六批已补离线接口。

时长/缩短时间价格并未从原服务端找回，本地选择明确写在 `server/local-gameplay.json`：幼年期 I 等待 1 小时，幼年期 II 等待 3 小时；两个阶段每石缩短 1 小时，剩余时间向上取整。本轮不宣称恢复原版价格。

依据：原 `GameWebAPI.cs` 的 010901/020102/010302 请求和响应、`CMD_DigiGarden.cs` 的成长扣石请求（stone 是持有余额）、`HouseGardenMonsterList.cs` 的培养禁用行为，以及原帮助数据中的花园规则。客户端 `TimeSpan.Hours` 计算适用于本轮不到 24 小时的时长；实际按钮金额和倒计时仍待游戏验证。

### Link 点循环

普通关卡 1–9 的原 `990905.worldDungeonM.linkPoint` 均为 20。本地单人胜利结算现按该值发放 Link 点，以资产类别 3 列入 `dropReward`，可累积至 300 点进行现有 Link 捕捉，所得幼年兽可进入普通花园。

奖励数额来自原主数据；选择在本地单人胜利发放属于本地重建规则，未声称恢复原版所有奖励触发语义。进场保存奖励快照，旧版本已开的战斗不会被追补新奖励；失败/撤退不发，原请求及历史战斗重试不重复发。上限使用原 `maxLinkPointCount=999999`，到上限时响应只列实际到账数量。

### 请求和存档修复

- 批量请求的每项响应独立复制，防止后续成长/改动共享对象，造成首次响应和缓存重试响应不一致。
- `Store.connect()` 统一提交或回滚并显式关闭 SQLite 连接，修复 Windows 上文件句柄滞留。本轮测试曾实际触发 `WinError 32`，修复后检查退出连接不可继续操作。
- 请求编号限制为原客户端声明的 Int32 范围，避免超大数字导致 SQLite 查询溢出/断开。
- 拒绝重复 JSON 字段、NaN/Infinity；无效批次不会保留前置修改或重试记录。
- HTTP 在未读完请求体就拒绝请求时关闭连接，防止残留字节污染后续请求；拒绝歧义长度和当前不支持的 Transfer-Encoding。
- 两个并发请求重放同一次捕捉，验证只扣一次、只增加一只。

## 第三批：农场友情互动

接通 010701 农场触摸互动、010702 友情倒计时。只对常用队伍中已持有、成长期及以上、非蛋且不在花园培养中的数码兽奖励，新手教学结束后开放；战斗未结算时不能改变友情或属性。010702 支持空位 `0`，非空响应固定补足三个槽位，空列表/教学期间保持 null，避免原 FarmDigimonManager 访问短数组越界。只读计时查询不重置冷却。

本次找到原 991002.helpM “友情度”说明：农场互动每只数码兽每天只能加一次友情。具体重置时刻、时区与每次增量未恢复，本地配置明确采用“成功互动后滚动 24 小时、每次 +1”。计时按账号和拥有编号持久化，换队、认证、服务实例重建不会清零；到期精确开放一次，失败批次不消耗机会，并发不同请求也只能奖励一次。达到成长阶段上限后不再增长，原 990112 上限仍是权威。原帮助提到战斗也可能增加友情，但该概率/数量尚未实现，不用虚构的胜利增量替代。

每 30 点门槛来自 riseConditionFriendShipStatus。原客户端的友情弹窗按本次跨门槛的增量计算 floor(maxStat*1%)；本地每次互动只加 1 点，故将每个门槛的取整增量累加，属性分别采用 maxHp/maxAttack/maxDefense/maxSpAttack/maxSpDefense/speed。避免 maxHp=566 时第二门槛保存 +6、弹窗展示 +5 的差异。服务端经验/喂食/普通进化重新计算基础属性后附加这些门槛奖励；同一物种不重复叠加，进化保留友情和冷却并按新物种重新计算。原服务端取整实现未恢复，本轮选择以互动弹窗的每次增量为准，完整游戏显示仍待验收。

未跨门槛时 upStatus=null，客户端用 upFriendship 本地增加友情；跨门槛时返回六项 upStatus 与完整 userMonster，客户端直接用服务器结果更新，不会再次加一次属性。再次点击仍在冷却时返回 upFriendship=0。已补相关中文拒绝提示。

五项定向测试覆盖：24 小时冷却/重连/上限/回滚；30 与 60 两个门槛取整一致及喂食/进化保留；三槽补齐/非法输入/账号与战斗保护；并发点击只奖励一次；冷却结束前一秒和精确到期边界/教学保护。证据在 `research/tests-friendship-targeted-20261001.log`；最新完整回归与静态检查见 `research/offline-check-latest.json`。最终完整回归 62 项通过（136.388 秒），24 个自建 Python、20 个 server JSON、3381 个资源目录项和全部33种设施模型/占地检查通过。正式存档、缓存版本和当前 APK 仍与本轮基线一致。全部使用临时数据库和随机回环端口，新增代码未加载正式服务。

## 第四批：强化、继承与素材保护

接通 010201 强化、010601 技能继承和 010001 锁定/解锁。素材消耗使用账号 SQLite 事务，任何后续批次失败均回滚金币、经验、技能、素材及操作收据。原 API 只有拥有编号和技能槽，无客户端价格字段；费用全部在服务端按原数据计算。

强化接受 1–5 个不同素材，禁止基础数码兽作为素材。每只素材经验为 fusionExp + fusionExpRise*(level-1)，金币为 (该经验+70)*原 reinforcementCoefficient=3。允许满级基础数码兽继续强化，符合客户端用于提升幸运的确认流程；经验仍封顶。匹配基础种族的素材按最高成长阶段提供 7/20/50/100% 幸运成功率（含装甲/混合体阶段），不将多只概率相加；不匹配种族不抽签。概率来自客户端 GetLuckUpChanceRateMax，本地成功 +1 幸运并按 maxLuck 封顶，普通 fusionType=1；成功增量、原大成功规则未恢复，明确记录在 local-gameplay.json，不虚构活动倍率或大成功。

继承需素材满级，基础数码兽不要求满级。第一技能槽可正常替换，第二槽要求原 rare>=6（版本升级）；素材所选槽必须有真实 type=2/3 继承技，禁止选择相同目标技能。价格依据 CMD_Succession：基础觉醒值 rare-1 加8，乘素材第一槽技能 inheritancePrice，再乘素材觉醒值 rare-1 加2，最后加400；即使选素材第二技能槽，原客户端也按第一槽技能计价。本轮匹配其确认金额。继承只替换所选槽，保留另一槽、必杀技、等级/经验、友情、幸运及才能数据。

素材禁止处于任何普通编队、锁定状态2/3、数码蛋/幼年期、花园培养或特殊训练类型中；未结算战斗禁止整个强化/继承操作。竞技场本身未开放，客户端名单当前为空，后续接通竞技场时仍需接入同等素材保护。010001 使用原字符串 setFlg=0/1，保留 statusFlgs 的另一位，并持久保存，基础数码兽锁定不妨碍强化/继承，锁定保护针对被消耗的素材。

素材删除会清掉芯片槽、农场引用和其友情计时；依据 ChipSlotData.RemoveMonsterChipData 将已装备芯片的 userMonsterId 重置为0，芯片仍在持有列表。同一材料组合的持久收据防止重认证或并发重放再次消耗/扣费/抽幸运；重连重复请求返回当前仍持有的基础数码兽，避免用旧快照覆盖后续进化或技能。跨操作、换基础对象、已经被其他操作消耗的素材仍拒绝。

所有捕捉、固定奖励和教学伙伴分配共享单调的 monster_id_sequence，消耗前保留最高编号、历史消耗编号不复用，避免旧友情倒计时、战斗历史或重试收据挂到新物件。经验属性重算同时保留原客户端使用的才能百分比（对等级基础属性取整）和友情门槛奖励，强化不会抹掉已有才能。

新增八项测试：费用/经验/芯片解绑/编号与重连收据、素材保护/余额/回滚/账号隔离、满级幸运/概率边界/封顶、究极体100%与特殊类型保护、并发素材消耗一次、普通继承含攻击与辅助技能、两个第二槽和第一槽计价、继承条件与锁定位保存。定向证据在 `research/tests-fusion-targeted-20261001.log`、`research/tests-inheritance-targeted-20261001.log`，最终完整回归70项通过（129.611秒），24个自建Python、20个server JSON、3381个资源目录项和33种设施检查通过；输入源码/配置/主数据前后指纹一致，正式存档/APK/缓存版本与本轮基线一致。最新报告为 `research/offline-check-latest.json`；游戏演出尚未启动。

## 第五批：才能继承

接通010502，响应仅包含完整userMonster，沿用原客户端按六项才能增量判断成功的方式。素材不要求满级，但必须有有效才能且能提升至少一项；基础对象可锁定，素材仍受所有队伍、锁定、数码蛋、花园、特殊类型与战斗状态保护。无可提升项目或金币不足时不扣费、不消耗，失败批次整体回滚。

原AbilityData与990117提供升级概率，倍率及初次继承率按素材成长阶段：成长期1倍/10%，成熟期1.2倍/20%，完全体1.5倍/35%，究极体2倍/50%，概率向下取到0.1%并封顶100%。已有银牌5至9、金牌15至19成功加一档，银牌10成功变金牌15；无牌成功继承素材完整档位，20封顶。无牌继承金牌失败保底银牌5，金牌达到990118上限后禁止新金牌，但保底仍保留，原有金牌可继续提升。

多项新金牌可能超过空位时，原帮助7确认随机选择金牌候选，其余留银牌；原服务端选择与掷骰的先后未恢复。本地明确采用各项独立判定后，从成功的新金牌中均匀选择保留，超额项取失败保底（无牌取5，原银牌10仍10），规则写入local-gameplay.json。不冒充原服务器随机实现，也不伪造活动倍率。

费用匹配CMD_MedalInherit.CalcCluster的单精度中间运算：最大才能的1.15次幂先按十分位向下取整再乘500，每增加一个素材才能乘数增加0.1。额外用C# MathF/float原式交叉核对30个费用组合：0/5/10/15/20最大才能与1至6项素材才能。最高档单素材实际8149，不能用十进制8150替代。六项才能百分比对等级基础属性取整，友情门槛独立追加；不会改变经验、技能、幸运与友情。

成功或失败均按原流程消耗素材和金币；ChipSlotData.RemoveChipData的delete=true仅删除槽位，芯片本身重置拥有者，保留库存。基础数码兽的芯片不解绑。持久收据、服务实例重建/重认证和并发请求防止再次扣款、消耗及抽取，重放返回当前持有基础对象，素材编号不复用。
